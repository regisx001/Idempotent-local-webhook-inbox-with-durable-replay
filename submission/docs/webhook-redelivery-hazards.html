The Webhook Redelivery & Race Condition Problem

Why naive consumers corrupt state when distributed webhook redeliveries cause duplicate executions, out-of-order stale updates, version collisions, and tenant cross-talk.

FAILURE MODE 1

Stale State Overwrite

  • Out-of-Order Packets: A network timeout causes Delivery 1 (v2) to be processed before delayed Delivery 2 (v1).
  • Regression: Without monotonic version checks, late-arriving v1 overwrites current v2, rolling back resolved tickets.

FAILURE MODE 2

Double-Processing & Conflicts

  • Redundant Retries: Upstream services redeliver identical events on slow acks, triggering repeated billing or ticket creation.
  • Payload Mutation: Re-using a delivery ID with conflicting parameters violates transactional idempotency.

FAILURE MODE 3

Tenant Bleed & File Corruption

  • Multi-Tenant Leaks: Unvalidated foreign tenant rows corrupt local state partitions.
  • Torn Writes: Writing directly to state files leaves 0-byte truncated JSON if power drops mid-save.
